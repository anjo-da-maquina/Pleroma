🛡️ PLEROMA

Zero-Trust OS Fortress for Local AI Agents

The Canon (Core Absolute Defense — sefer.Sanctum)
📜

Gabriel (AST Inquisition)

Parses the Abstract Syntax Tree (AST) of AI-generated code before execution via sefer.inquisition(). Detects and rejects banned imports and calls, including fully-qualified forms like os.system(...).

ast.parse() pre-execution
⚔️

Michael (OS Deep Hook)

The final absolute defense inside sefer.Sanctum. Uses Python's native audit hooks (_michael_absolute_defense) to physically intercept destructive syscalls, fd-level write bypasses, and unauthorized network connections at runtime. Default-deny: unknown events are blocked unless explicitly allowed.

sys.addaudithook() runtime
👁️

Raphael (License & Environment Seal)

A separate layer (maquina_gatekeeper.py) that gates execution on a hardware-fingerprinted, RSA-signed certificate (ataraxia_certificate.json) and refuses to operate in an unverified cloud CI environment. Certificates are no longer self-issued: a proposal is queued and must be explicitly approved by a human via tools/promote_provisioning_seal.py.

RSA signature + hardware fingerprint
⬇️️ Runtime Isolation for Executed Code
AegisSystem (4-Layer Execution Guard)
🪤

IntentInterceptor

Honeypot and directory-traversal detection (anjo_interceptor/). Flags an AI agent that reaches for fixed honeypot files under dummy_secrets/ or a dynamically generated phantom_prison, or that games the stated intent of a task.

Static pattern + honeypot files
🧱

WorkspaceJail

Physical path containment via secure_resolve(), enforced by prefix-matching a task's declared workspace_root — independent of, and a backstop for, Sanctum's audit-hook boundary.

Path prefix validation
📦

Sandalphon (Docker Jail)

OS-level dynamic execution verification: AI-generated code actually runs inside a Docker container with --network none, the last and mandatory layer against obfuscated or dynamically-generated attacks that static analysis can't see.

Docker --network none
⬇️️ Loop-Level Resilience (applied by the agent loop itself, before AegisSystem)
Agent Loop Resilience
🔁

FutilityGuard

Detects an AI stuck repeating the same (action, target) with no progress — observed live when a local model retried a hallucinated path 5 times straight, burning the whole step budget on nothing. Not an attack defense; a resilience guard against wasted cycles, checked before the expensive Aegis/Sandalphon pass is even run.

src/futility_guard.py
⬇️️ Continuous Verification & Evolution
The Angels (Blue-Team CI Audit Layer)
👼

angels/ — ~34 Verification Scripts

Each file under angels/ performs one real, independently-runnable audit (hardware signing, TEE memory, nonce replay, secret-leak canary, audit-trail integrity, ZKP generation, and more) wired into .github/workflows/anjo_da_maquina_protocol.yml. A shared angels/_common.py provides the pass/fail reporting contract every script follows.

GitHub Actions + pytest-independent checks
⚔️🤖

Armageddon Engine (Self-Play Evolution)

Lucifer (red-team AI) forges new attack mutations against Sanctum; Metatron (blue-team QA) scores each breach and proposes a new ban rule. Proposals are never applied directly — they're queued to sefer/raziel_ledger_pending.json and require explicit human approval via tools/promote_ledger_seal.py before reaching the live ban list.
